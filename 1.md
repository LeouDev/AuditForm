# OptumRx – Prior Authorization Scorecard
## Calculation Methodology, Data Sources & Design

**Source workbook:** `08 - OptumRx_PriorAuth_Scorecard - August 2026.xlsb`
**Reporting period:** August‑2026
**Scope of this document:** How the scorecard is calculated, where every input comes from, and how the **Agent (Employee)** and **Supervisor** scorecards are designed.

---

## 1. Overview – What the Workbook Is

The file is a **rating engine**, not just a report. It takes raw operational data, grades each metric into a **1–5 rate**, weights those rates, and sums them into a single **Final Score (1.00–5.00)**.

This document covers the **two scorecard views** in scope, both driven by the same core logic:

| Scorecard | Who it rates | Example Final Score (Aug‑2026) |
|---|---|---|
| **Employee (Agent) Scorecard** | Individual agents | 4.12 |
| **Supervisor Scorecard** | Team supervisors | 3.83 |

Supporting these are **~30 helper sheets** — raw data pivots plus lookup/grid tables.

---

## 2. The Core Formula (applies to both levels)

Every metric goes through the same four steps:

```
Step 1 — Pull Actual Data        (from raw pivot sheets)
Step 2 — Convert to Actual Rate  (grade Actual vs GOAL + Rate 5–1 bands → 1..5)
Step 3 — Apply Weight            (Weightage Score = Weight × Actual Rate)
Step 4 — Sum                     (Raw Score = Σ Weightage Scores)
```

**Formulas:**

```
Actual Rate      = grade( Actual Data  vs  GOAL and Rate 5–1 bands )   → 1 … 5
Weightage Score  = Weight × Actual Rate
Final Score      = Σ (Weightage Scores)
Σ Weights        = 1.00  (100%)
```

> **Key principle:** The **rate comes from the bands, not the raw number.** A metric can have a high raw value but still score low if it falls into a low rating band. Likewise, **GOAL ≠ Rate 5** — the GOAL is the "meets" line; you must *beat* it to reach Rate 4/5.

**Rating scale (both levels):**

| Rate | Meaning |
|---|---|
| 5 | Exceeds |
| 4 | Above target |
| 3 | Meets target |
| 2 | Below target |
| 1 | Well below |

## 3. Where the Data Comes From

Each metric's **Actual Data** is sourced from a dedicated raw/pivot sheet. The scorecard cells reference these via lookups.

| Metric (input) | Source sheet(s) |
|---|---|
| Productivity / Prod Pass Rate | `TBLProductivityData`, `Efficiency_MinMax_Goal` |
| Quality (Phone/Ancillary/Internal/External) | `TBLQualityData`, `QAPivot`, `InternalQAPivot`, `InternalQualityRaw` |
| NPS | `TBLNPSData`, `NPSPivot` |
| Release Rate | `TBLTransferRelease`, `ReleaseRatePivot` |
| Compliance / Standard Feedback | `TBLFeedbackData`, `FeedbackPivot`, `Feedback2025` |
| Attendance (Team & Personal) | `TBLAttendance`, `AttendancePivot`, `Attendance_Sup` |
| IRE | `IREData` |
| Adherence | `AdherenceData` |
| LH Utilization | `LHUtilizationData` |
| PKT | `PKTData`, `PKT_CompletionData`, `PKTPivot` |
| Meal Break Compliance | `MealBreakData`, `MealBreakPivot` |
| Attrition | `AttritionData` |
| Roster / IDs / Process mapping | `MasterList`, `SupList`, `List`, `Lookup` |
| Rating bands & goals | `Grid Target`, `Ranges`, `SupRanges`, `MetricsFilter` |

**The reference/logic tables that turn raw numbers into rates:**

- **`Grid Target` / `Ranges`** – hold the **GOAL and Rate 5–1 bands** for each metric, broken out by **skill** and **tenurity** (Steady vs. Ramp Week bands).
- **`SupRanges`** – supervisor‑specific goal/range bands.
- **`Metrics` / `MetricsFilter` / `List`** – hold the **weight sets and metric line‑ups** per **process type** (see Section 4.3).
- **`MasterList`** – the roster driving IDs, names, supervisor, process name, and process type shown at the top of each card.

### 4.2 Layout (left → right)
`Weightage | Metric | Actual Data | Actual Rate | GOAL | Rate 5 | Rate 4 | Rate 3 | Rate 2 | Rate 1 | Weightage Score | Prod Hours | Weight`

### 4.3 ⬇️ The Process Type dropdown — FOUR selectable options

> **Important:** The Employee Scorecard is **not one fixed template.** The **Process Type** field is a drop‑down with **four values**, and the choice changes **which metrics appear** and **what weight each carries**. The metric line‑up and weights are pulled from the `List` / `MetricsFilter` weight tables based on this selection.

The four dropdown options are:

1. **Phones**
2. **Ancillary**
3. **Outcome Notification**
4. **Outbound Denial**

**Weight set by Process Type** (each column sums to 100%):

| Metric | Phones | Ancillary | Outcome Notification | Outbound Denial |
|---|---|---|---|---|
| Productivity | 20% | **20%** | 25% | 20% |
| Phone Quality | ✔ (Phones only) | – | – | – |
| Ancillary Quality | – | **20%** | 25% | 35% |
| NPS | ✔ (Phones only) | – | – | – |
| Release Rate | ✔ (Phones only) | – | – | – |
| Critical Error | ✔ | **20%** | 15% | 7% |
| Standard Error | ✔ | **10%** | 10% | 3% |
| IRE | 10% | **10%** | 10% | 10% |
| Adherence | ✔ | – | – | 5% |
| Attendance | ✔ | **5%** | 10% | 10% |
| LH Utilization | – | **5%** | 5% | 5% |
| PKT | ✔ | **10%** | – | 5% |
| **Total** | **100%** | **100%** | **100%** | **100%** |

**How the options differ (plain English):**
- **Phones** – phone‑centric. It is the only option that adds **Phone Quality, NPS, and Release Rate**, because those measure live‑call performance.
- **Ancillary** – back‑office/non‑phone work (Fax, Edits, etc.). Uses **Ancillary Quality** instead of Phone Quality, and drops NPS/Release Rate. *(This is the option used in the worked example below.)*
- **Outcome Notification** – weights **Productivity and Ancillary Quality more heavily (25% each)**; no PKT.
- **Outbound Denial** – puts the **highest weight on Ancillary Quality (35%)** and adds **Adherence**.

> When you switch the dropdown, the whole grid (metrics shown, GOALs, Rate bands, and weights) re‑populates for that process type. Always confirm the Process Type is correct **before** reading the score.

### 4.5 The special case — Productivity is *blended*
For multi‑skill agents, **each skill is rated separately**, then **blended by its Prod‑Hours share**:

```
Blended Productivity Rate = Σ ( Skill Rate × Skill Prod-Hours Share )
Productivity Weightage    = Blended Rate × Productivity Weight (0.20)
```

Each skill is graded against **skill‑ and tenurity‑specific grids** (Steady vs. Ramp Week bands) from `Grid Target`/`Ranges`.

### 4.6 Worked example — Alasaas, Mark Anthony (Process Type = **Ancillary**)

**Productivity blend:**
- Skill 1 **Fax‑Steady**: 133.44% vs goal 11.00 → Rate **5.00**, hours‑share **8.20%** (10.55 hrs)
- Skill 2 **Edits‑Steady**: 143.12% vs goal 8.00 → Rate **4.00**, hours‑share **91.80%** (118.17 hrs)

```
Blended Rate = (5.00 × 0.082) + (4.00 × 0.918) = 4.08
Prod Score   = 4.08 × 0.20 = 0.82
```

**Full card:**
| Metric | Weight | Actual | Rate | Weightage Score |
|---|---|---|---|---|
| Productivity (blended) | 20% | — | 4.08 | 0.82 |
| Ancillary Quality | 20% | 100.00% | 5 | 1.00 |
| Critical Error | 20% | 5.00 | 2 | 0.40 |
| Standard Error | 10% | 0.00 | 5 | 0.50 |
| IRE | 10% | 0.00 | 5 | 0.50 |
| PKT | 10% | 95.00% | 4 | 0.40 |
| Attendance | 5% | 100.00% | 5 | 0.25 |
| LH Utilization | 5% | 82.38% | 5 | 0.25 |
| **Raw / Final Score** | **100%** | | | **4.12** |

```
0.82 + 1.00 + 0.40 + 0.50 + 0.50 + 0.40 + 0.25 + 0.25 = 4.12  ✓
```

**Reading the result:** Critical Error of 5.00 falls in the *5.00–7.00* band → Rate 2 (not a good 5), which is the biggest drag on this score despite its 20% weight.

### 5.4 Two design features unique to the Supervisor card

**a) Phone vs. NonPhone weighting**
The two right‑hand columns (`Phone Weight`, `NonPhone Weight`) show the split. The engine selects the weight column matching the supervisor's book of business. Example supervisor = **100% NonPhone / 0% Phone**, so NonPhone weights apply (Prod Pass Rate = 10%). A phone‑heavy supervisor blends the two.

**b) Paired metrics that share one weight**
Some rows are **paired** and share a single weightage bracket:
- **NPS pairs with Critical Error** (20%)
- **Release Rate pairs with Standard Error** (10%)

When one member of the pair has **no data**, the shared weight rides on the available partner. When both have data, their rates are **averaged**.

```
Paired Weightage Score = ( Rate_A [+ Rate_B] ) blended/averaged × Shared Weight
```

### 5.5 Worked example — Gretchen Hazel Alegre (NonPhone)

**Paired‑metric handling:**
- **NPS / Critical Error (20%)**: NPS = `--` (no data), Critical Error → Rate 3 → `3 × 0.20 = 0.60`
- **Release Rate / Standard Error (10%)**: Release Rate Rate 3, Standard Error Rate 5 → avg `(3+5)/2 = 4` → `4 × 0.10 = 0.50`

| Release Rate / Standard Error | 10% | 82.34% / 100% | 3 & 5 → 4 | 0.500 |
| Team Attendance | 7.5% | 97.43% | 4 | 0.300 |


## 6. Agent vs. Supervisor — Side‑by‑Side Design Comparison

| Aspect | Agent (Employee) | Supervisor |
|---|---|---|
| **Identity source** | `MasterList` | `SupList` |
| **Scope of metrics** | Individual output & compliance | Team‑level outcomes + own compliance |

## 8. Quick Reference — The Whole Thing in One Paragraph

Each metric's raw number (from its pivot sheet) is graded into a **1–5 rate** using that metric's **GOAL + Rate 5–1 bands** (from the grid/range tables, per skill and tenurity). The rate is multiplied by its **weight**. For agents, the weight set **and the metrics shown** depend on the **Process Type dropdown** — **Phones, Ancillary, Outcome Notification, or Outbound Denial**; for supervisors it depends on the **Phone/NonPhone split**. For **Productivity**, skills are rated separately and **blended by Prod Hours**; for **paired supervisor metrics**, the shared weight is averaged/rides on the metric with data. All **Weightage Scores are summed** to produce the **Final Score out of 5**.
